问题2：推送镜像到 SWR 报错 Invalid image, fail to parse
'manifest.json'
现象：所有层推送成功，但最终报 manifest 解析错误。
原因：Docker 29.x 默认生成 OCI 格式 manifest，华为云 SWR 仅支持经典 Docker 格式。
解决方法：构建时加 --provenance=false 参数：
1

docker build --provenance=false -t <镜像地址> .

问题3：CCE 集群节点资源不足（Insufficient memory）
现象：新 Pod 持续 Pending，describe 显示 Insufficient memory 。
原因：2 个 c7.large.2（4GiB）节点实际可调度内存约 2.4GiB/节点，系统 Pod 占用较多，应用 Pod 叠加后空间
不足。
解决方法：向集群添加第3个节点（2 vCPU / 8 GiB），metrics-server 和应用 Pod 调度恢复正常。

问题4：跨 Region 拉取 SWR 镜像失败（ImagePullBackOff）
现象：CCE 集群在 cn-east-3，镜像存储在 cn-north-4 SWR，Pod 启动报 ImagePullBackOff。
原因：K8s 节点拉取私有镜像需要认证，跨 Region 访问需要 imagePullSecret。
解决方法：
1. 在 cn-east-3 SWR 创建同名组织并重新推送镜像
2. 创建 imagePullSecret：
1

kubectl create secret docker-registry swr-secret \

2

--docker-server=swr.cn-east-3.myhuaweicloud.com \

3

--docker-username=cn-east-3@<AK> \

4

--docker-password=<SK>

3. 在 Deployment 中引用该 Secret

问题5：ConfigMap subPath 挂载不支持热更新
现象：修改 ConfigMap 后，Pod 内文件不自动同步。
原因：Kubernetes 已知限制——使用 subPath 挂载时，ConfigMap 更新不会自动传播到 Pod。
解决方法：修改 ConfigMap 后手动删除 Pod，让 Deployment 重建 Pod 读取最新配置。

问题7：Spark executor Pod 因资源不足无法调度（FailedScheduling）
现象：SparkApplication 提交后 driver 正常运行，executor Pod 持续 Pending， describe 显示：
1

0/3 nodes are available: 1 Insufficient cpu, 2 Insufficient memory

原因分析：
kubectl top nodes 显示节点实际 CPU 使用率仅 2-3%，但调度器依据的是资源请求（requests）而非

实际用量
大节点（2vCPU/8GiB）CPU 请求已达 90%（1755m/1950m），仅剩约 195m 空闲
executor 默认请求 1 核（1000m）CPU，无法调度到任何节点
解决方法（分两步）：
第一步：临时缩容现有应用，释放内存压力：
1

kubectl scale deployment frontend --replicas=0

2

kubectl scale deployment backend --replicas=0

3

kubectl scale deployment redis --replicas=0

第二步：在 SparkApplication executor 配置中，用 coreRequest 将 Kubernetes CPU 请求与 Spark 逻辑核心
数解耦：
1

executor:

2

cores: 1

3

coreRequest: "100m"

4

instances: 1

5

memory: "512m"

6

memoryOverhead: "128m"

# Spark 内部仍按 1 核调度任务
# Kubernetes 仅预留 100m CPU，匹配节点剩余 195m

验证：executor Pod 成功 Running，作业输出：
1

Top 10 words: [('spark', 8), ('hello', 7), ('data', 4), ...]

问题10：Worker Pod StartError（/usr/sbin/sshd not found）
现象：MPIJob Worker Pod 报 StartError，describe 显示 exec: "/usr/sbin/sshd": no such file or
directory 。

原因：MPI Operator 要求 Worker 容器内有 sshd，用于 Launcher 与 Worker 之间的 SSH 通信。自建镜像未安
装 openssh-server。
解决方法：Dockerfile 中增加 openssh-server openssh-client 并创建 /var/run/sshd 目录，重建镜像。

问题11：MPIJob apiVersion 不匹配
现象： kubectl apply -f mpijob.yaml 报错 no matches for kind "MPIJob" in version
"kubeflow.org/v1" 。

原因：mpi-operator v0.4.0 的 CRD 只注册了 v2beta1 ，YAML 中写的是 kubeflow.org/v1 。
解决方法：将所有 MPIJob YAML 的 apiVersion 改为 kubeflow.org/v2beta1 。

附加题2：CI/CD 流水线
问题15：GitHub Actions 流水线 4 秒失败（Secrets 未配置）
现象：推送代码后 Actions 自动触发， Login to SWR 步骤 4 秒内失败，日志显示 -u cn-east-3@ / -p （密
码为空）。
原因： .github/workflows/deploy.yml 引用了 ${{ secrets.SWR_AK }} 和 ${{ secrets.SWR_SK }} ，但
仓库 Settings → Secrets 中尚未添加这两个值。
解决方法：GitHub 仓库 → Settings → Secrets and variables → Actions → New repository secret，分别添加
SWR_AK （华为云 AK）、 SWR_SK （SWR 临时登录密钥）、 KUBE_CONFIG （base64 编码的 kubeconfig）。

问题16：SWR 登录报 Authenticate Error
现象：Secrets 配置后重新触发， Login to SWR 步骤仍报 Authenticate Error 。
原因： SWR_SK 填写的是 IAM 账号的永久 SK，而华为云 SWR 的 docker login 需要使用 SWR 临时登录密钥（24
小时有效），两者不同。
解决方法：进入 SWR 控制台 → 右上角"登录指令"→ 复制其中 -p 后面的临时 Token，更新 GitHub Secrets 中
的 SWR_SK 。

问题21：CCE Pod 出方向连接外部 MQTT Broker 被安全策略拦截
现象：CCE 中的 mqtt-subscriber Pod 连接 broker.emqx.io:1883 和 broker.emqx.io:8883 均报
socket.timeout: timed out ，添加安全组出方向 1883 规则后仍无效。

原因：华为云 CCE 集群出方向流量受 VPC ACL 或更底层的网络策略限制，1883/8883 端口被静默丢弃，安全组
规则不足以覆盖所有层级的过滤。
解决方法：在 CCE 内部自建 Mosquitto Broker，完全绕过出方向防火墙：
订阅者连接 mosquitto-svc:1883 （ClusterIP，内部通信，无防火墙限制）
K3s 传感器连接 mosquitto-lb 的 ELB 公网 IP（入方向流量，不受出方向限制）
关键 Mosquitto 配置（ConfigMap）：
1

listener 1883

2

allow_anonymous true
